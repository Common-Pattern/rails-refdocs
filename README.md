# rails-refdocs

Local, greppable reference docs for a Ruby on Rails app's stack: the API
references and guides for Ruby, Rails, PostgreSQL, Hotwire (Turbo and
Stimulus), ViewComponent, Bootstrap and the Rails gems around them, as
Markdown in the app's own `reference/` folder, at the versions the app uses.

It exists so a coding agent (or a person) works from the documentation for
the exact versions in the app rather than from memory: `grep` finds the
guide, `METHODS.tsv` finds the method, `sed -n` reads it.

A Ruby gem with a Rails integration. It runs in the app's own Ruby and needs
nothing else: downloads go through `Net::HTTP`, archives are read with
RubyGems' tar reader, the Ruby and Rails API docs are generated by rdoc
in-process, and the PostgreSQL manual is converted to Markdown with Nokogiri.
Linux and macOS (rdoc runs in a forked process).

## Topics

| Topic | Source | Version from |
| --- | --- | --- |
| `ruby` | release tarball, rdoc: core and stdlib API, syntax and NEWS pages, `CLASSES.tsv`/`METHODS.tsv` | `.ruby-version`, then the lockfile's `RUBY VERSION` |
| `rails` | the tag: Rails Guides and the full API by rdoc, with indexes | `rails` in `Gemfile.lock` |
| `postgres` | the release's HTML docs tarball: the whole manual, one file per page, `TITLES.tsv` | a pin (nothing locks the server) |
| `view_component` | the tag: `docs/` and README | `view_component` |
| `bootstrap` | the tag: documentation site sources and `scss/` | `bootstrap` |
| `turbo` | turbo.hotwired.dev handbook and reference, turbo-rails and turbo READMEs | `turbo-rails` (the site is untagged) |
| `stimulus` | stimulus.hotwired.dev handbook and reference, stimulus-rails and stimulus READMEs | `stimulus-rails` (the site is untagged) |
| `importmap-rails`, `dartsass-rails`, `letter_opener_web` | README at the tag | the gem of the same name |
| `solid_queue` | README, UPGRADING and `docs/` at the tag | `solid_queue` |

`rails-refdocs topics` prints the list.

## Use in a Rails app

```ruby
# Gemfile
group :development do
  gem "rails-refdocs", github: "Common-Pattern/rails-refdocs", tag: "v0.2.0"
end
```

```sh
bundle install
bin/rails generate rails_refdocs:install
bin/refdocs update
```

The generator writes `reference/TOPICS` from the gems in `Gemfile.lock`, adds
`bin/refdocs`, and ignores the generated folders:

```gitignore
/reference/*
!/reference/README.md
!/reference/TOPICS
!/reference/VERSIONS
```

Commit `reference/TOPICS`, `reference/VERSIONS` and `reference/README.md`
(generated: versions, where things are, how to search).

`reference/TOPICS` names the topics, one per line, each with an optional pin.
A topic's version is, in order:

1. its pin in `TOPICS`. A pin is a version prefix: `rails 8.1` resolves to
   the latest 8.1.x release, `postgres 18` to the latest 18.x,
   `bootstrap 5.3.8` to exactly that;
2. the version locked in the app's `Gemfile.lock` (Ruby: `.ruby-version`);
3. the latest release.

So a Rails app pins only `postgres`, and every `bundle update` moves the docs
with it:

```
ruby
rails
postgres 18
view_component
bootstrap
turbo
stimulus
```

```sh
bin/refdocs update                # fetch what is missing or behind
bin/refdocs update rails          # one topic
bin/refdocs update --force ruby   # fetch again regardless
bin/refdocs check                 # recorded vs resolved versions; exit 1 if behind
bin/refdocs check --locked        # offline: exit 1 if VERSIONS is behind Gemfile.lock
bin/refdocs link                  # in a git worktree: symlink the main checkout's topics
```

The same commands are rake tasks: `bin/rails refdocs:update`,
`refdocs:check`, `refdocs:locked`, `refdocs:link` (topics as task
arguments, `refdocs:update[rails,ruby]`; `FORCE=1` refetches).

`check --locked` reads only `TOPICS`, `VERSIONS`, `Gemfile.lock` and
`.ruby-version`, so CI can run it without network access: a dependency bump
that was not followed by `bin/refdocs update` fails the build.

`--dir DIR` points at a folder other than `reference/` at the top of the
current checkout, `--root DIR` at an app root other than its parent (where
`Gemfile.lock` and `.ruby-version` are read). `REFDOCS_COMMAND` sets how the
generated README spells the command.

## Outside Rails

```sh
gem install rails-refdocs
rails-refdocs --dir path/to/app/reference update
```

## Output

The generated Ruby and Rails API files come from the rdoc in the app's bundle,
so everyone on one lockfile gets the same files. Newer rdoc releases parse
some sources differently; after an rdoc upgrade run
`bin/refdocs update --force ruby rails`. Markdown is written with backticks
and `*`/`**` on every rdoc version (rdoc 7.1 and later otherwise fall back to
`<code>` and `<strong>` tags).

The PostgreSQL converter reproduces the output of pandoc (`gfm-raw_html`,
`--wrap=none`, with the Lua filter the 0.1 script used): for the 18.6 manual,
1145 of 1148 pages are byte-identical and the other three differ by one blank
line or list separator. Tables are flattened into lists (one item per row,
cells in order); links point at the `.md` pages.

Downloads come from rubygems.org, registry.npmjs.org, github.com,
codeload.github.com, raw.githubusercontent.com, cache.ruby-lang.org and
ftp.postgresql.org, over any `https_proxy` in the environment.

## Worktrees

The topic folders are gitignored, so a new git worktree has none. `link`
symlinks each topic folder of the main checkout's `reference/` into the
worktree, so parallel worktrees share one copy; it does nothing in the main
checkout. Search through the links with `grep -R` or `rg -uuL`: `grep -r` and
plain `rg` do not follow symlinks below the path they are given. Running
`update` in a worktree replaces that worktree's links with its own copies and
leaves the main checkout's alone.

## Adding a topic

A topic is a `RailsRefdocs::Topic` subclass in `lib/rails_refdocs/topics/`
listed in `RailsRefdocs::Topics::ALL`. It defines `name`, `title`, `source`
(the VERSIONS and README source column), `layout` (its README entry),
`latest(pin)` (the newest release under a pin), `fetch(version, stage,
work_dir)` (writes the topic into `stage`) and, when a gem carries its
version, `lock_gem`.

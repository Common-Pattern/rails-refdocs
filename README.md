# rails-refdocs

Local, greppable reference docs for a Ruby on Rails app's stack: the API
references and guides for Ruby, Rails, PostgreSQL, Hotwire (Turbo and
Stimulus), ViewComponent, Bootstrap and the Rails gems around them, as
Markdown in the app's own `reference/` folder, at the versions the app uses.

It exists so a coding agent (or a person) works from the documentation for
the exact versions in the app rather than from memory: `grep` finds the
guide, `METHODS.tsv` finds the method, `sed -n` reads it.

One Bash script. It needs curl, git, jq, tar, and podman or docker: Ruby and
Rails API docs are generated by rdoc inside `ruby:<version>-slim`, and the
PostgreSQL manual is converted by pandoc inside `pandoc/core`. Nothing else is
installed on the host.

## Topics

| Topic | Source | Pin |
| --- | --- | --- |
| `ruby` | release tarball, rdoc: core and stdlib API, syntax and NEWS pages, `CLASSES.tsv`/`METHODS.tsv` | yes |
| `rails` | the tag: Rails Guides and the full API by rdoc, with indexes | yes |
| `postgres` | the release's HTML docs tarball, pandoc: the whole manual, one file per page, `TITLES.tsv` | yes |
| `view_component` | the tag: `docs/` and README | yes |
| `bootstrap` | the tag: documentation site sources and `scss/` | yes |
| `turbo` | turbo.hotwired.dev handbook and reference, turbo-rails and turbo READMEs | no |
| `stimulus` | stimulus.hotwired.dev handbook and reference, stimulus-rails and stimulus READMEs | no |
| `importmap-rails`, `dartsass-rails`, `letter_opener_web` | README at the tag | yes |
| `solid_queue` | README, UPGRADING and `docs/` at the tag | yes |

`rails-refdocs topics` prints the list.

## Use in an app

`reference/TOPICS` names the topics, one per line, each with an optional pin.
A pin is a version prefix: `rails 8.1` resolves to the latest 8.1.x release,
`postgres 18` to the latest 18.x, `bootstrap 5.3.8` to exactly that. Without
one the latest release is used. Pin to what the app's `Gemfile.lock`,
importmap and database image hold.

```
ruby 4.0
rails 8.1
postgres 18
view_component 4
bootstrap 5.3.8
turbo
stimulus
```

Commit `reference/TOPICS`, `reference/VERSIONS` and `reference/README.md`
(generated: versions, where things are, how to search) and ignore the rest:

```gitignore
/reference/*
!/reference/README.md
!/reference/TOPICS
!/reference/VERSIONS
```

Then:

```sh
rails-refdocs update              # fetch what is missing or behind its pin
rails-refdocs update rails        # one topic
rails-refdocs update --force ruby # fetch again regardless
rails-refdocs check               # recorded vs resolved versions, fetches nothing
rails-refdocs link                # in a git worktree: symlink the main checkout's topics
```

`--dir DIR` points at a folder other than `reference/` at the top of the
current checkout. `REFDOCS_COMMAND` sets how the generated README spells the
command, for apps that call it through a wrapper.

A wrapper that pins a release of this repo and caches it:

```bash
#!/usr/bin/env bash
set -euo pipefail
ref=v0.1.0
root="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cache="${XDG_CACHE_HOME:-$HOME/.cache}/rails-refdocs/$ref"
if [[ ! -x "$cache/rails-refdocs" ]]; then
  mkdir -p "$(dirname "$cache")"
  tmp="$(mktemp -d "$cache.XXXXXX")"
  git -c advice.detachedHead=false clone --quiet --depth 1 --branch "$ref" https://github.com/Common-Pattern/rails-refdocs "$tmp"
  mv -T "$tmp" "$cache" 2>/dev/null || rm -rf "$tmp"
fi
REFDOCS_COMMAND=scripts/refdocs exec "$cache/rails-refdocs" --dir "$root/reference" "$@"
```

## Worktrees

The topic folders are gitignored, so a new git worktree has none. `link`
symlinks each topic folder of the main checkout's `reference/` into the
worktree, so parallel worktrees share one copy; it does nothing in the main
checkout. Search through the links with `grep -R` or `rg -uuL`: `grep -r` and
plain `rg` do not follow symlinks below the path they are given. Running
`update` in a worktree replaces that worktree's links with its own copies and
leaves the main checkout's alone.

## Adding a topic

A topic is a name in `KNOWN_TOPICS` plus one arm in each of
`resolve_topic_version` (the version for a pin), `fetch_<topic>` (writes into
the staging folder it is given), `topic_source`, `fetch_topic`,
`topic_layout` (its README entry) and, where the name needs it,
`topic_title`. Check with `shellcheck rails-refdocs`.
